# HextechBrawl 3.4.0 · 共享成长的武器肉鸽

普通海克斯卡展示武器图标、名称、颜色、类别和获得等级。选择后获得武器及海克斯效果。核心原则：保留旧武器与更换新武器承接同一套基础成长，不再因为反复给同一实例加等级而压倒其他选择。

## 3.4.0：从单件滚雪球改成共享进度

- 取消“每手必定给当前武器”的保底。有足够合法武器时，每手至少两项对应当前未携带的种类；仍遵守颜色、近远程与多发兼容规则。
- 绑定成长改为整局共享：每次正常选择积累一层，新获得的海克斯武器直接承接全部层数。旧物品的获得时间不再造成输出差距。
- 每层4%伤害，最高+100%；每层1.5%攻速，最高+45%。用户要求的绑定直接武器伤害基准×2保留，派生攻击不重复翻倍。
- 锻造改为共享最高档位+1/+2/+3，而不是在现有物品等级上重复加数。只能升到更高档，可跳档；已达到的档位和低档不能重复选。
- 锻造奖励的三色属性只随该次有效升档发一次。跳到+3后不会再出现+1/+2供刷属性。
- 等级目标为 `min(30, max(本关原版掉落等级 + 共享最高锻造档位, 已记录的绑定等级下限))`。同一关反复选择不会把+3再次加在旧等级上。
- 选择确认后，当前携带的绑定物品一起追赶共享等级与普通锻造品质。以后取得的海克斯武器也继承这些进度；普通品质最高S，不复制传奇和原生特殊词条。
- 同名绑定物品可以保留原实例、原词条和弹药；它只追赶共享目标，不额外累加等级。换新类型不会从零培养，但原生招式、暴击条件与特殊词条仍然不同。

旧局已投入的高等级不直接下调：携带旧绑定武器的等级记录为共享下限，旧锻造记录折算为已达到的档位。新物品也能达到该下限，解除旧物品专属的等级优势。过去已获得的三色属性不回收。

## 开局池：颜色 → 分类

每局自动赠送一次定向卷轴，在安全时机直接弹出界面，不生成地面实体。

1. 红/紫/绿三选一：武器必须包含所选原版颜色标签。
2. 近战/远程二选一：本局分类锁定，不能靠重随改变。

盾牌不是第三类，必须满足颜色条件，再兼容所选近战池或远程池。双色只要任一标签匹配即可。例如ThrowingTorch（投掷火把）为战术/暴虐：红色远程和紫色远程均可出现，红色近战不行；纯紫武器不会进入红色池。

目录从只读res/data.cdb提取114件可掉落单槽武器/盾牌：原版group4近战、5远程、6盾，颜色读取tier1/tier2。双槽武器及其副手暂不入池。其他模组修改标签时静态目录不会自动更新。换新发生在已锁定的颜色/类别内，不解锁另一类池。

开局颜色沿用基础路线：红=兵器大师（武器伤害+15%、受伤+10%），紫=奥术工程师（附伤+25%、武器伤害-10%），绿=壁垒守卫（生命+20%、攻速-10%）。开局两步不计入正常选择次数。

## 三选一与发放

每手尽量为三张不同强化与三种不同武器。机制池未耗尽时至少一项战斗机制，如连锁闪电、吸血、持续伤害、暴击节奏、脉冲、穿墙或多发。

优先避开最近两手展示的6个词条和最近两次所选词条，兼顾品级、不同流派、未获得强化及路线；不足时回退补齐。锻造仅25%概率尝试插入，每手最多一张，升档后两次后续正常选择不出现锻造。达到+3后全部锻造退出候选。

候选整体洗牌，不固定第一列。颜色/类别、特殊能力兼容条件和武器池数量可能限制换新保底；例如多发卡必须配适配的远程武器。有足够合法备选时至少两项不是当前携带种类，池不足时按实际情况回退。

每手至少一项不要求金币、细胞或新增诅咒，但仍可能带卡面注明的持续代价。候选及对应武器一起保存；切换W、退出读档不重抽，R才消耗一次重随。更新不强行替换已保存的当前候选，新规则从下一手或重随生效；旧候选中已完成的锻造会拒绝扣费并提示。

确认后直接进入指定库存位置。W选择两个武器槽或已有背包中的替换位置。旧物品掉在脚边保留；同名绑定回炉保持原位置。指定双槽武器时拒绝交易，请先卸下或指定其他位置。

每次正常选择获得一层所选主色的原版属性；不再按选择次数额外指数增加伤害/生命。核心自然成长、碎片升级及六流派2/4种羁绊保留，不免费治疗。

## 锻造与资源契约

| 卡牌 | 共享锻造进度 | 代价及属性 |
| --- | --- | --- |
| 金币精锻 | 提升至+1 | 300金币，红紫绿各+1 |
| 细胞熔铸 | 提升至+2 | 15细胞，红紫绿各+1 |
| 诅咒锻造 | 提升至+3 | 10原版诅咒，红紫绿各+1 |

可以直接跳档，但低档不会在之后重新提供。每张锻造只可选一次，也不能通过同名回炉重置。品质继承是普通QualityUp，最多3层S；传奇词条不共享。

其他交易：染血借贷获得1000金币并增加12诅咒；灵魂透支获得30细胞但减少治疗；赎罪支付600金币减少10诅咒并降低伤害；细胞献祭支付25细胞换红紫绿各+2并降低生命；背负厄运增加15诅咒换伤害。原版击杀解咒和受伤死亡保留，不灭核心不能阻止诅咒死亡。

当前常驻伤害代价连乘最低保留60%；相位穿墙和散射的独立代价另算。核心面板显示绑定基准、共享层数、共享锻造档位与常驻代价。

## 穿墙与多发

- 相位穿墙：两类池可出现。绑定近战在原攻击范围内忽略命中视线遮挡，原生Bullet弹丸ignoreWalls=true；绑定攻击伤害-10%。不改变敌人视线或扩大原攻击范围。独立碰撞/瞄准的特殊武器仍需实测。
- 散射弹幕：仅远程池，卡上只配适配弓弩、桶炮或投掷火把，不配盾牌及未适配光束/范围法术。一次发射3组，额外两组约±7.45度，每发45%伤害；三组全中理论135%。额外两组不消耗/回收额外弹药，原生多箭按3组处理。

## 操作、存档与验证

- 1/2/3、鼠标，或方向键+Enter选择；W指定替换位置；R重随。
- F6开关核心，Tab切换核心/选牌，G消耗碎片升级核心，Esc暂存候选并继续游戏。
- 保留三卡弹出、回弹、品质光晕、悬停与确认退场动效。
- DCCM SaveData保存路线、候选、共享层数、等级下限、品质及锻造进度；物品本体由游戏保存，新局重置。

规则检查112,904项通过，包含100种种子×100轮基础回归、固定关卡50次选择不滚等级、同一锻造20次重复申请被拒绝、旧局等级共享，以及2,000手换新候选回归。新增共享装备刷新与对局平衡尚未实机验证，按用户安排未启动游戏或改动其存档。

构建需要本地游戏、DCCM 35.15.1、.NET 11 SDK，并配置DCCM_MDK_ROOT。

```powershell
dotnet run --project HextechBrawl/Tests/RulesCheck.csproj -c Release
dotnet build HextechBrawl/HextechBrawl/HextechBrawl.csproj -c Release
```

自动安装到coremod/mods/HextechBrawl，正常保存退出并重启游戏后加载。仓库不包含游戏代理运行库、反编译代码、存档、日志或游戏素材。图标读取本地res/cardIcons.png，武器元数据引用本地res/data.cdb，均不覆盖或复制。GamePseudocode及res始终只读。

## 源码

- HextechBrawl/RunState.cs：共享武器库、开局/候选、锻造档位与旧局衔接。
- HextechBrawl/Contracts.cs：原版费用、属性、库存替换与共享装备追赶。
- HextechBrawl/WeaponPool.cs：颜色/分类目录；Catalogue.cs：强化/契约定义。
- HextechBrawl/Combat.cs、WeaponAbilities.cs、VolleyHooks.cs：伤害和能力实现。
- HextechBrawl/HexView.cs：卡面预览和核心；Main.cs：生命周期和输入。
- Tests/Program.cs：纯规则测试；CHANGELOG.md：版本变化。

通过DCCM文档中的生成Hook、更新事件与SaveData机制实现，原版接口签名对照本机代理和只读伪代码。代码由Codex协助编写，游戏资源与DCCM归其原作者；尚未指定开源许可证。
